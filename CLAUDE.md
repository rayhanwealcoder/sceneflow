# SceneFlow — working notes for Claude Code

- Spec: `docs/SceneFlow_AI_Implementation_Handoff_v1.0.md` (source of truth). Work goes **phase by phase**; after each phase update `CHANGELOG.md` + `docs/architecture.md`, then tell the user what was built, how to try it, and what is next. Phases done: 1–10 (all phases of the handoff doc) + MP4 export (Phase 11) + scroll pin engine / custom thumbnail / speed / page speed (Phase 12, 2026-11-10) + e-mail / password reset / account page (Phase 13, 2026-11-10) + super admin console (Phase 14) + WordPress.org readiness / plugin 0.7.0 / admin support tools (Phase 15) + temporary password / sign-in link / e-mail change / comment + approval mails / Elementor + Bricks elements / sales from a video / analytics CSV + retention / WebM, GIF, 4K exports (Phase 16, plugin + runtime 0.8.0, 2026-11-10); next: deploy (VPS or the free hybrid in the README), billing.
- The user writes Banglish (Bengali in Latin letters); reply in Banglish. Keep end-user UX simple — no learning curve, guided (tour, goal picker, diagnostics).
- Everything lives in this repo: https://github.com/rayhanwealcoder/sceneflow (branch `main`). Commit/push only when the user asks ("git add koro" / "push koro").
- **No Docker, no Redis, never WAMP.** Local Postgres 17; queue is pg-boss. WordPress testing uses the LocalWP site **`development.local`** (WP-CLI via LocalWP's PHP, see below).
- Connectors are released from here as zips: `pnpm build:connectors` → `dist/connectors/*.zip` + `manifest.json`. **"wp build"** from the user means: `pnpm build && pnpm build:wp`, then hand over `dist/connectors/sceneflow-wordpress.zip`. New platform = new folder under `connectors/` with `connector.json` + get-started `README.md`.
- Keep both placement methods in WordPress: `[sceneflow id="…"]` shortcode/block **and** element-pick placements.
- **Prefix rule (WP.org: no 2–3 letter prefixes)**: plugin PHP `SceneFlow_`/`sceneflow_`; runtime DOM classes `sceneflow-*` (root `.sceneflow-root`; `.sceneflow-player` is the connector's container, never reuse it), `data-sceneflow-*`, `--sceneflow-*`, storage keys `sceneflow_*`. Never add a new `sf-` name to anything that ships. Printed player HTML goes through `wp_kses( …, SceneFlow_Frontend::allowed_html() )` written out at the echo (phpcs does not accept wrappers). Analytics is opt-in (option `sceneflow_analytics` = '1'); `wp-landing.mjs` turns it on as the site owner. Run `pnpm check:wp` (phpcs + wp-prettier + .pot + PHP tests) after touching the plugin; regenerate the .pot with `wp i18n make-pot` (needs `-d extension=curl -d extension=openssl` for block.json).
- WordPress plugin must stay WordPress.org-clean: `phpcs --standard=WordPress --extensions=php --ignore="*/tests/*" connectors/wordpress/sceneflow` and `wp plugin check sceneflow` (Plugin Check plugin on development.local) before calling a phase done. Plugin tests: `pnpm test:wp` (needs the fixture from `pnpm --filter @sceneflow/server test`).
- Verify before reporting: `pnpm typecheck`, `pnpm test` (needs DB `sceneflow_test`), `pnpm build`, PHP tests + phpcs + Plugin Check, and an end-to-end script against the running stack (`scripts/smoke.mjs` or a phase-specific one in `scripts/e2e/`). Browser-level checks use `playwright-core` with the installed Chrome (`channel: "chrome"`, never download browsers): `scripts/e2e/pages.mjs` (every page, fails on any page error — run after any editor/web change; it caught a zustand 5 selector loop), `scripts/e2e/scroll-smoothness.mjs`, `scripts/e2e/analytics.mjs`, `scripts/e2e/ai.mjs` (`--record` writes `dist/walkthrough/sceneflow-walkthrough.mp4`).
- zustand 5: selectors that return a new array/object must be wrapped in `useShallow`, or React loops under transitions (#185).
- Agency (Phase 10): clients / invites / dashboard in `apps/api/src/routes/workspace.ts`, comments + approval + client review link in `routes/review.ts`; approval is bound to the draft *checksum* (autosave rewrites the draft version in place); admins always publish, editors need an approved unchanged draft when `approvalRequired`. Web pages: `/dashboard`, `/team`, `/join/:token`, `/review/:token` (public). `scripts/e2e/agency.mjs` covers the whole flow in three browser contexts.
- MP4 export (Phase 11): `apps/worker/src/export.ts` renders the frozen config in headless **Google Chrome** (playwright-core, `channel: "chrome"`, `EXPORT_BROWSER` override) with the published runtime, CDP screenshots (JPEG q92) → FFmpeg H.264, audio mixed from source files via `audioPlan`/`audioFilterGraph` (`packages/server/src/export/plan.ts`; bundled FFmpeg is 2018 — no `amix normalize`, use apad + volume=N + alimiter). Rows in `video_exports`, queue `export.render`, routes `apps/api/src/routes/exports.ts`, UI `apps/web/components/ExportCard.tsx`. E2E: `scripts/e2e/export.mjs`. Worker test skips without Chrome.
- Scroll scrub (Phase 12): **no GSAP** (user rule). `packages/core/src/scroll.ts` is the pure math (`pinState`, `triggerProgress`, `pinTypeFor`); the player picks sticky / fixed / transform pinning per page (`data-sf-pin`) and measures progress from `getBoundingClientRect()`, never `scrollY` — needed for smooth-scroll themes (development.local's hello-animation theme uses GSAP ScrollSmoother: fixed wrapper + transformed content, where sticky and fixed cannot work). `scrollDistance` = travel while pinned (ScrollTrigger semantics). Custom thumbnail frames come from the worker (`media.frame`); `canvas.background: "transparent"` + autoplay + no controls = the "no visible player" look. WordPress test page: `scripts/e2e/wp-landing.mjs` (uses `make-demo-clip.mjs` for a Chrome-rendered product clip — never `testsrc2` for anything the user will look at — and `landing-template.mjs` for the page; no 1 px hairlines on smooth-scroll themes, they shimmer during the glide regardless of SceneFlow).
- E-mail (Phase 13): `packages/server/src/mail` — Resend / SMTP (nodemailer) / **outbox folder** fallback (`<STORAGE_DIR>/outbox/*.json`, links in the API log) so forgot-password and invitations work without a mail server; `MAIL_*` in `apps/api/.env` (and `apps/worker/.env` for "your video is ready"). Reset links: `password_resets`, 60 min, single use, same answer for unknown addresses, mail sent after the response (`sendLater`). Pages `/forgot`, `/reset/:token`, `/account`. E2E: `scripts/e2e/account.mjs` (needs the API without `MAIL_*`, it reads the outbox).
- Super admin (Phase 14): `users.platform_role = super_admin`, granted only by `pnpm admin grant <email>` (CLI, `apps/api/src/cli/admin.ts`) or another super admin; never from `.env`. API `apps/api/src/routes/admin.ts` (404 for everyone else, every write → `admin_audit`), UI `/admin` (`apps/web/components/admin/*`), worker heartbeat `worker_heartbeats`. E2E `scripts/e2e/admin.mjs` grants a throwaway account and revokes it at the end. The user's own account is not a super admin until they run the grant themselves.
- Phase 16: password-setup sessions (`sessions.password_setup`) are refused by `requireUser()` unless the route passes `allowPasswordSetup`; add that only to routes the "choose your own password" step needs. Revenue attribution is pull-based (`lib/orders.ts`, plugin `class-sceneflow-orders.php`, header `X-SceneFlow-Source`, at most one pull per site per minute when an Analytics page opens). The WooCommerce adapter must never send the Store API `Cart-Token` (it moves the cart into a side session; the site's cart page stays empty). Export formats live in `packages/server/src/export/plan.ts` (`EXPORT_FORMATS`, `exportLimitError`, `useOriginalSource`). `wp-sales.mjs` reuses the account paired with development.local (pairing a new workspace moves the site); `wp-bricks.mjs` tests Bricks on **bricks-try.local** (MySQL 10065, `E:/Local Sites/try-bricks`) and deactivates the plugin there afterwards; Bricks only saves page content for a user who may use the builder (`--user=admin`), and that site's preloader keeps elements "invisible" to Playwright (wait for `state: "attached"`). `account.mjs` spends the forgot-password limit (5 per 15 min): run it on a freshly started API.
- AI (Phase 9) is provider-based and optional: without keys the API uses starter text + the OS voice (Windows SAPI here). Keys go in `apps/api/.env` (`ANTHROPIC_API_KEY`, `ELEVENLABS_API_KEY`). Claude is called only through `@anthropic-ai/sdk`; every drizzle user lists `@opentelemetry/api` so drizzle resolves once (the SDK pulls it in). "Properly test with dummy content" = generate a clip with FFmpeg (`testsrc2`), run it through the real pipeline, measure in Chrome.

## Local tooling (this machine)

- LocalWP PHP: `D:\programs\local\resources\extraResources\lightning-services\php-8.2.27+1\bin\win64\php.exe`; WP-CLI phar: `D:\programs\local\resources\extraResources\bin\wp-cli\wp-cli.phar`. Run as
  `php -d extension_dir=<phpdir>/ext -d extension=mysqli -d extension=openssl -d extension=mbstring -d extension=curl -d extension=gd -d mysqli.default_port=10005 wp-cli.phar --path="C:/Users/UseR/Local Sites/development/app/public" <command>` (quote `--fields=ID,user_login` in PowerShell).
- phpcs: `C:\Users\UseR\AppData\Roaming\Composer\vendor\bin\phpcs.bat`.
- Ports: API 4800 (LocalWP owns 4000), web 3000. Stopping background servers can leave orphan node processes — kill by port before restarting. **The worker has no port**: orphan workers from earlier sessions keep pulling pg-boss jobs with stale code (seen 2026-11-10: four day-old workers, uploads processed without renditions). Before starting a worker list `Get-CimInstance Win32_Process -Filter "name='node.exe'" | ? { $_.CommandLine -match 'tsx src/index.ts' }` and `taskkill //PID … //F` every one that is not the current API (port 4800 owner) or worker.
- The Bash tool truncates commands longer than ~8 KB (Windows command-line limit) — a long heredoc then fails with "unexpected EOF while looking for matching `''". Write big files in two heredoc parts (`file.p1`, `file.p2`) and `cat` them together, or use the Write tool. Non-ASCII in heredocs is fine except `•` (use `•`).
- Killing node processes from a PowerShell listing inside a bash `while read` loop silently fails (CRLF in the PID); use `taskkill //PID <n> //F` per PID and re-list. The admin System tab shows every worker's heartbeat: two online workers = one is stale. Node's first lookup of a `.local` host on Windows can exceed the connector's 10 s timeout (seen with development.local); retry once before calling it a bug.
- Zips: use bsdtar (`tar -a -c -f`), not `Compress-Archive`.
